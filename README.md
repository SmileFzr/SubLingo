# SubLingo · 双语字幕

**一个浏览器插件（不是独立程序）** —— 抓取视频网站自身的字幕，实时逐句翻译并叠加成双语字幕，读起来比平台自带的机翻更顺。

> 原项目为 YouTube 专用（youtube-subtitle-translator），v3.1 起重构为多站点引擎。

## 🚀 主要功能

* **实时双语字幕**：上行译文、下行原文，一次看懂——**任何语种**（英/日/韩/法/德…）都按这个格式呈现。
* **多站点适配**：按站点 DOM 结构适配 + 通用探测 + 原生字幕轨道，三级降级，尽量不漏。
* **样式预设**：影院 / 课堂 / 极简 / 高对比，一键切换，参数实时生效。
* **精细调节**：译文字号与**原文字号各自独立**调节（默认原文 68%，即译文大、原文小）、最多行数、底色不透明度、文字色、底色色值、是否显示原文。
* **全屏可用**：字幕层会跟随进入全屏容器（旧版在全屏下会消失）。
* **拖拽定位**：按住 **Alt** 拖动字幕，位置按比例记忆，换分辨率、切全屏都不会跑位；按住 **Alt** 拖动**左右边缘**可以调字幕框宽度。
* **原生字幕优先**：站点本来就有字幕时（YouTube CC、B 站字幕等）直接用它的文本，不再跑 AI 识别——更准、零延迟，也不会出现"刚看过的那句又重复一遍"。
* **二刷秒出字幕**：第一遍播完会把「时间 + 原文 + 译文」存成时间轴，再看同一集直接按播放进度回放，不用等识别。
* **本地字幕**：加载 `.srt` / `.vtt`，按播放进度对齐翻译——站点本身不提供字幕时也能用。
* **AI 语音识别**：视频完全没有字幕时，用本地 Whisper 直接"听"音频生成字幕。音频不出本机，不需要任何 API Key。
* **导出 SRT**：把看过的双语字幕导出为标准 `.srt`，可直接二次利用。
* **样式隔离**：字幕层跑在 Shadow DOM 里，不受站点 CSS 污染，也不会污染站点。

## 🎬 支持站点

| 站点 | 字幕来源 | 状态 |
| --- | --- | --- |
| YouTube | 站内 CC（`.ytp-caption-segment`） | ✅ 原生适配 |
| 哔哩哔哩 | 站内 CC（`.bpx-player-subtitle-panel`） | ✅ 原生适配 |
| Twitch | 站内 CC 容器 / 字幕轨道 | ✅ 有字幕时可用 |
| Kick | video.js 字幕层 | ✅ 有字幕时可用 |
| TikTok | 站内字幕 DOM / **AI 语音识别** / 本地文件 | ✅ 无字幕视频可用 AI 识别 |
| Vimeo / Dailymotion / niconico / 爱奇艺 / 优酷 / X / Facebook / Coursera | 通用探测 + 轨道 | ⚠️ 视站点而定 |
| 其它任意网站 | 点弹窗里「此站启用」授权后注入 | ⚠️ 视站点而定 |

**关于硬字幕**：TikTok、Kick、Twitch 上大量内容的字幕是"烧"在画面像素里的，DOM 中拿不到文本，任何读取 DOM 的插件都无能为力。这类视频有三条出路：

1. 用弹窗里的 **AI 语音识别**：直接识别声音，不依赖画面或 DOM（推荐，TikTok 这类视频大多根本没人声以外的文字）；
2. 用弹窗里的 **本地字幕** 加载 `.srt` / `.vtt`；
3. 画面 OCR（识别烧在像素里的字）尚未实现，见文末路线图。

## 🛠️ 安装

1. 下载本仓库（Code → Download ZIP）并解压。
2. 浏览器打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
3. 打开右上角 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择解压后的文件夹。
5. 打开视频页，点扩展图标调样式。

## 🧭 使用提示

* 视频需要**先开启站点自带字幕**（YouTube 的 CC、B 站的字幕按钮），插件才有文本可抓。
* 状态条会显示当前字幕来源：`站内字幕已接管` / `原生字幕轨道` / `本地字幕文件` / `暂未检测到字幕源`。
* 换视频后如果没反应，点一下 **重新检测字幕**。
* 字幕挡住画面时：**Alt + 拖动**可以挪位置，**Alt + 拖左右边缘**可以改宽度，两者都会记住。
* 站内已有字幕时点「开启 AI 识别」会先提示一句——直接用原生字幕更快。确实要用识别（比如原生字幕语种不对），**再点一次**即可强制启动。
* 弹窗里所有调整都是**实时生效**的，不需要点"应用"。
* 字幕只在**播放页**显示。从播放页返回到搜索列表、首页、频道页时会自动收起并交还站点原生字幕——这些页面里的悬停预览播放器不会被误当成正在观看的视频。

## 🎙️ AI 语音识别（本地运行）

视频完全没有字幕时，插件用 [Transformers.js](https://github.com/huggingface/transformers.js) 在**你自己的电脑上**运行 OpenAI Whisper，从标签页音频里"听"出文字，再走正常的翻译 → 双语渲染管线。

**音频不会离开本机**：没有服务器、没有 API Key、没有按量计费。首次使用会下载模型权重，之后缓存在浏览器里，不重复下载。

### 怎么用

1. 打开视频页，点扩展图标；
2. 在「AI 语音识别」里选档位，点 **开启**；
3. 浏览器会询问「读取标签页音频」——这是把声音送进本地识别所必需的；
4. 状态变成 `本地识别中` 后，字幕会逐句出现。

> **第一次会多一步**：Chrome 只在"扩展刚被点击"时授予该标签页的音频权限，而授权弹窗本身会消耗掉这次点击。所以首次授权后如果提示「请关闭弹窗 → 再点一次扩展图标」，照做即可，第二次起就一键直接开。
>
> 同理，**页面刷新或跳转后授权会失效**，重新点一下扩展图标就好。
>
> 如果报错，点错误文字旁边的 **复制诊断**，会把版本、页面地址、AI 会话状态和插件自己的日志一并复制出来——不需要翻几千行控制台。

### 三档模型

| 档位 | 体积 | 说明 |
| --- | --- | --- |
| 快速 (tiny) | ~40MB | **默认**。绝大多数电脑跑得动，中文偶有错字 |
| 均衡 (base) | ~80MB | 准确率明显更好，单次推理耗时约翻倍 |
| 精准 (small) | ~200MB | 最准，对 CPU 要求高，低配机器会跟不上语速 |

### ⚠️ 三个必须知道的限制

1. **延迟 2–5 秒**。Whisper 的声学编码器固定按 30 秒窗口计算，所以单次推理耗时**与音频长短几乎无关**——实测 tiny 档单次约 2.5–4 秒（纯 CPU、单线程 WASM）。字幕在说完一句之后才出现，不是逐字上屏。
2. **中文会错字**。Whisper 对中文弱于英文，tiny 档约 20–30% 字符错误（大意能懂）。要求高就换 base / small。
3. **DRM 加密内容取不到音频**（Netflix、Disney+ 等），这是浏览器层面的硬限制。

> 为什么要"读取标签页音频"权限：MV3 里拿标签页声音唯一的通道是 `chrome.tabCapture`，没有替代方案。插件把它做成了**可选权限**——不开 AI 识别就不会请求。

### 实现要点

```
tabCapture → offscreen 文档（把流回接扬声器，否则标签页会静音）
           → AudioWorklet 重采样到 16kHz、按 100ms 切批、多声道下混单声道
           → Worker 内的 Whisper（WASM）+ 能量切句 + 幻觉过滤
           → 送入既有的翻译 / 双语渲染 / 拖拽 / 导出管线
```

踩过的坑都写进代码注释了，其中三个值得单独提：**捕获后必须回接扬声器**（不回接用户一开字幕视频就没声音）、**Whisper 在静音和纯 BGM 上会幻觉**（凭空生成"谢谢观看"这类句子，有黑名单 + 能量校验双保险）、**推理必须串行**（并发会瞬间吃掉几百 MB 内存）。

### 已知的模型加载问题

模型权重从 HuggingFace 下载。若你所在网络访问 `huggingface.co` 不通，插件会自动回退到 `hf-mirror.com`。但有用户反馈部分镜像的 `/resolve/` 跳转在浏览器里无法跟随（服务端跳转到 CDN 时缺跨域许可），这种情况下模型下载会失败并显示 `模型载入失败`。临时办法是用代理直连官方站点，或把模型文件手动放入扩展目录后用本地模型路径加载。

## ⚠️ 翻译接口说明

使用 `https://translate.googleapis.com/translate_a/single`（Google 翻译非官方公共接口），免费、无需密钥，但不保证长期可用；请求过多时会被限流，插件内置了重试与原文兜底。

语种判断按**字符集**区分汉字 / 假名 / 谚文，不会把韩语、日语字幕误认成"已经是中文"而跳过翻译；自动检测若把短句判错（原样返回），会按字符集给出显式源语言再试一次。

## 📝 更新日志

**v3.6.0**
* 修复：**同一句字幕反复堆成一整屏**（截图里那种 "who is the man who is the man…"）。这是 Whisper 在 BGM / 回声上的**复读幻觉**，一段音频被反复输出几十遍。现在两道闸：周期性片段压缩（同一片段连续 ≥3 次只留一次）+ 4-gram 重复率超过 45% 直接判为幻觉丢弃；单条字幕也限制在 190 字以内，显示层再按行数兜一层。
* 修复：**AI 识别和站内字幕同时存在，导致"刚看过的那句又重复一遍"**。现在站内已有字幕就不跑 AI：点「开启」时先提示（再点一次可强制启动）；万一识别已经在跑，检测到原生字幕会自动停用并提示，省掉 8~10 秒延迟。
* 新增：**二刷回放**。第一遍播完（覆盖到全片 60% 以上）会把时间轴存进本地，下次打开同一集直接按 `currentTime` 取字幕——零延迟、不烧 CPU。存 24 部，超出按时间淘汰；时长对不上（同一链接换了片子）就自动忽略。
* 新增：**Alt 拖动左右边缘调字幕宽度**，宽度写入设置，换页/全屏都保持；「重置位置」会一并还原宽度。
* 改进：滑窗把上一句原样带回来、且只多出几个字时，不再重复上屏。

**v3.5.0**
* 修复：**切到下一个直播间/视频后，字幕会先冒出上一场的 1~2 句**。原因有两层——① Worker 里还压着上一场最多 4.5 秒的音频；② 已经提交的那次推理 3.8 秒后才返回，内容却属于上一个主播。现在页面一换（SPA 导航或整页跳转）就给识别端发 `RESET`：清空音频缓冲、语种锁定和判重状态，并用**世代号**把在途结果整段丢弃（`gen` 不一致就不上屏）。
* 修复：换页后字幕层若不立即收起，会短暂显示在跟本没有播放器的新页面上。现在导航时立刻清场并丢弃发往非播放页的识别结果。
* 新增：切到**另一个标签页**看视频时，新页面右下角会提示「AI 字幕正在另一个标签页识别 · 「<标签标题>」」。`tabCapture` 一次只能捕获一个标签，且换标签必须重新点图标授权——先把话说清楚，比让人对着不动的画面猜要好。
* 新增：弹窗里若会话在别的标签页，状态栏显示「在另一个标签页识别 · <标题>」，不再误报成"本页监听中"。
* 改进：停止识别后立即收起字幕层，不用等 9 秒静默超时。

**v3.4.1**
* 修复：直播间里 `(结束)` / `（エンディング）` / `(咳)` / `（拍手）` 这类**片尾与拟声标签**仍会漏上屏。标签表补上 ending / エンディング / 結末 / 结束 / 拍手 / 無音 / 沈黙 / 咳 / ゴホン。第一版正则只匹配了单词，而 Whisper 实际输出带修饰词和日文写法。

* 说明：延迟的物理下限 = 单段时长 + 一次推理耗时。本机（WASM 单线程 + base）一次推理约 3.8 秒，所以再怎么调也降不到 4 秒以下；想更快只能换引擎（流式 ASR），换更小的模型会牺牲识别质量。

**v3.4.0**
* 修复：AI 识别只出 `(music)` / `(laughs)`，主播说话一句都没转出来。三个原因一起处理：
  * 默认模型从 `tiny` 换成 `base`。tiny 在**非英语 + 有背景音乐**的场景下几乎认不出人声（实测日语直播间只吐 `(music)`），base 才是可用起点。老用户升级后会自动迁移到 base，想省性能可以手动切回「快速」。
  * **声音标签不再上屏**：`(music)`、`(soft music)`、`[Music playing]`、`(audience laughing)`、`♪` 这类 Whisper 的"声音描述"会被剥掉；剥完没有实质文字就丢弃，不会再用一行「（音乐）」挡住画面。
  * **语种锁定**：自动检测模式下，一旦识别出第一句人声，就按字符集（假名/谚文/汉字）把 `language` 固定下来，不让它每段重新猜——短音频 + BGM 时语言误判是幻觉的主要来源。
* 改进：切句窗口从 8.5 秒缩短到 5.5 秒。窗口越长，BGM 和人声越容易糊成一段被模型当成"音乐"；更短的段更容易只框住一句人声。
* 改进：语音门限从 `噪声底 × 2.6` 降到 `× 1.8`。直播间 BGM 是持续声，会把噪声底一路推高，原来的门限反而把人声挡在门外；噪音段由标签过滤兜底。
* 新增：连续 3 段只有音乐/噪音时，状态栏提示「只听到音乐/噪音 · 试试指定源语言」，而不是让用户对着空画面猜是不是坏了。
* 修复：下载模型时进度每秒推十几次，把 120 条诊断日志环形缓冲刷满，真正有用的信息全被挤掉。现在只记录状态变化，并给每条识别结果记一行 `rms / 段长 / 耗时 / 文本`。
* 新增：推理跟不上时（长段 + 慢机器）自动丢弃段落前半部分，避免延迟和内存无上限增长。

## 🗺️ 路线图

* **画面 OCR（识别烧进像素的字幕）** —— 用 Tesseract.js 在本地识别字幕带，靠帧差分只在画面变化时触发。适合"有字幕但被压进画面"的影视 / 教学视频；对 TikTok 那种文字位置乱跳的效果一般。
* **GPU 加速** —— 目前是纯 CPU。WebGPU 后端已留好开关，但实测在软件渲染环境下反而慢 20 倍，需要真实显卡才有意义。
* **更快的模型** —— Moonshine 一类针对短音频优化的模型，主要覆盖英语内容。
* **翻译引擎可选** —— 现在只有 Google 公共接口，可增加本地翻译模型以彻底离线。
